# Интеграция термостата Terneo для Home Assistant

[English](README.md) | Русский

<img width="2000" height="334" alt="4c8grq59fdbxs708khd8hru46i0iqvxv" src="https://github.com/user-attachments/assets/fecdffe1-d71b-4e64-84e9-54028a8cd8b5" />

Кастомный компонент для Home Assistant для управления термостатами Terneo через локальный API.

## Поддерживаемые устройства

Интеграция поддерживает как старые, так и новые версии термостатов Terneo:

- **Старая версия (OZ без датчика воздуха)** — устройства, выпущенные до июня 2025 года
- **Новая версия (OZ с датчиком воздуха / AZ)** — устройства, выпущенные с июня 2025 года

Интеграция автоматически определяет версию устройства при настройке и, начиная с v1.1.0, использует фактический набор параметров, возвращаемый `cmd:1`, чтобы показывать только те возможности, которые поддерживает данный термостат/прошивка.

## История изменений

### 1.1.1

- Исправлен опрос локального API на прошивках, которые требуют поля `time` и `auth` даже при отключённых блокировках LAN/cloud.
- Запросы чтения теперь отправляются компактным JSON, чтобы избежать пустых ответов встроенного API.
- Добавлен read-only зонд `tools/probe_terneo.py` для проверки HTTP, MQTT и UDP-анонсов.

### Климат-объект

- Включение/выключение
- Задание целевой температуры
- Переключение между режимами нагрева/охлаждения
- Режимы расписания (AUTO) и ручной (HEAT/COOL)
- preset-режимы: Schedule, Manual

### Датчики

- Температура пола
- Температура воздуха (только новая версия)
- Целевая температура
- Подключённая мощность (Вт)
- Гистерезис
- Коррекция датчиков

### Мониторинг энергии

- **Estimated Heating Energy** — расчётное накопленное потребление в кВт·ч (совместимо с долгосрочной статистикой)
- **Heating Time** — накопленное время включения реле в часах
- **Estimated Current Power** — настроенная мощность нагревателя при активном реле, иначе 0 Вт
- **Heating Active** — индикатор состояния реле (On/Off)

Счётчики расчётной энергии и времени нагрева сохраняются Home Assistant и переживают перезапуск интеграции/Home Assistant. При обновлении с 1.0.x интеграция пытается перенести предыдущие восстановленные значения датчиков.

> **Примечание:** значения энергии/мощности являются расчётными и основаны на настроенной подключённой мощности и состоянии реле; это не показания счётчика электроэнергии.

### Диагностика (v1.1.0)

Диагностические сущности создаются только тогда, когда устройство сообщает соответствующий ключ телеметрии, и по умолчанию отключены. Среди них:

- Wi-Fi RSSI
- Температура внутри корпуса и MCU
- Влажность датчика воздуха
- Оставшееся время таймера
- Последние причины перезагрузки
- Сообщаемый шаг уставки
- Обрыв/короткое замыкание датчика пола
- Потеря датчика воздуха / подключение / низкий заряд батареи
- Внутренний перегрев и ошибка контроля перегрева
- Ошибки синхронизации/хода времени
- Ошибка детекции нулевого перехода
- Предупреждение о длительной нагрузке и пропорциональный аварийный режим
- Диагностика API: последовательные ошибки статуса, последние успешные обновления статуса/параметров, последняя ошибка API

Все диагностические данные телеметрии устройства используют уже существующий опрос `cmd:4` и не добавляют дополнительных периодических HTTP-запросов.

### Переключатели

- Включение/выключение питания
- Блокировка от детей
- Режим охлаждения (вместо нагрева)
- Преднагрев
- Ночная яркость
- Обнаружение открытого окна (только новая версия)

### Числовые элементы управления

- Яркость дисплея (0–10)
- Гистерезис

### Элементы выбора

- Тип управления:
  - Датчик пола
  - Датчик воздуха (только новая версия)
  - Воздух с ограничением по полу (только новая версия)

### Сервисы

- `terneo.set_floor_limits` — задать минимальный/максимальный предел температуры пола
- `terneo.set_air_limits` — задать минимальный/максимальный предел температуры воздуха (только новая версия)

## Установка

### HACS (рекомендуется)

1. Откройте HACS в Home Assistant
2. Перейдите в раздел «Интеграции»
3. Откройте меню из трёх точек и выберите «Пользовательские репозитории»
4. Добавьте URL этого репозитория с категорией «Integration»
5. Установите «Terneo Thermostat»
6. Перезапустите Home Assistant

### Ручная установка

1. Скопируйте папку `custom_components/terneo` в каталог `config/custom_components`
2. Перезапустите Home Assistant

## Настройка

### Настройка через GUI (рекомендуется)

1. Перейдите в **Настройки** → **Устройства и службы**
2. Нажмите **+ Добавить интеграцию**
3. Найдите «Terneo»
4. Введите IP-адрес и серийный номер вашего термостата
5. Интеграция автоматически определит версию устройства и поддерживаемые возможности

Чтобы позже изменить IP-адрес/имя хоста, используйте **Переконфигурировать** в записи интеграции, а не удаление и повторное добавление термостата.

### Параметры конфигурации

После добавления интеграции можно настроить:

- **Интервал обновления** — как часто опрашивается текущий статус через `cmd:4` (10–300 секунд, по умолчанию 10)
- **Таймаут подключения** — таймаут HTTP-запроса (7–120 секунд, по умолчанию 7)

Полный набор параметров (`cmd:1`) обновляется отдельно каждые 120 секунд, чтобы снизить нагрузку на API термостата. Запросы чтения повторяются один раз после кратковременных таймаутов/некорректных ответов, а термостат помечается недоступным только после трёх последовательных неудачных циклов опроса статуса.

## Документация по API

Интеграция использует локальный API Terneo:

- [Справочник API](https://terneo-api.readthedocs.io/)
- [Параметры](https://terneo-api.readthedocs.io/parameters.html)
- [Команды](https://terneo-api.readthedocs.io/commands.html)

### Примечание по безопасности

По умолчанию управление через локальный API без токена безопасности заблокировано на устройстве. Чтобы включить локальное управление, установите параметр `bLc` в значение `oFF` на термостате.

- [Безопасность](https://terneo-api.readthedocs.io/safety.html)

## Поддерживаемые параметры

### Общие параметры (обе версии)

| Параметр | Описание |
|----------|----------|
| mode | Режим работы: расписание=0, ручной=3 |
| controlType | Тип управления: пол=0, воздух=1, воздух с ограничением по полу=2 |
| manualFloorTemperature | Уставка пола в ручном режиме |
| awayFloorTemperature | Уставка пола в режиме «не дома» |
| hysteresis | Гистерезис температуры |
| brightness | Яркость дисплея (0–10) |
| upperLimit / lowerLimit | Пределы температуры пола |
| powerOff | Состояние питания устройства |
| childrenLock | Блокировка от детей |
| coolingControlWay | Нагрев=0, охлаждение=1 |
| preControl | Режим преднагрева |
| useNightBright | Режим ночной яркости |

### Только новая версия

| Параметр | Описание |
|----------|----------|
| manualAir | Уставка воздуха в ручном режиме |
| awayAir | Уставка воздуха в режиме «не дома» |
| upperAirLimit / lowerAirLimit | Пределы температуры воздуха |
| minTempAdvancedMode / maxTempAdvancedMode | Пределы пола в режиме управления по воздуху |
| airCorrection | Коррекция датчика воздуха |
| bleSensorInterval | Интервал опроса беспроводного датчика |
| windowOpenControl | Обнаружение открытого окна |

## Устранение неполадок

### Не удаётся подключиться к устройству

- Убедитесь, что термостат подключён к вашей сети
- Проверьте правильность IP-адреса
- Убедитесь, что локальный API включён (`bLc` = `oFF`)

### Команды не работают

- Проверьте, отключён ли `lanBlock` (параметр 114)
- Убедитесь, что устройство не находится в режиме «только облако»

### Зонд для чтения API

`tools/probe_terneo.py` — диагностический помощник. Он сравнивает старый формат запроса с форматом с полями `time`/`auth`, может подписываться на MQTT-телеметрию и слушать UDP-анонсы. Он никогда не публикует сообщения и не меняет настройки устройства. Секреты читаются из переменных окружения (`TERNEO_TOTP_KEY`, `TERNEO_MQTT_HOST`, `TERNEO_MQTT_PORT`, `TERNEO_MQTT_USER`, `TERNEO_MQTT_PASS`) и никогда не выводятся.

```bash
python3 tools/probe_terneo.py --mode http --host <IP> --sn <SERIAL> --cmd 4
python3 tools/probe_terneo.py --mode mqtt --mqtt-topic 'pub_terneo/+/get/#'
python3 tools/probe_terneo.py --mode broadcast --seconds 10
```

Запустите `python3 tools/probe_terneo.py --help`, чтобы увидеть все параметры. Скрипт сообщает, чего не хватает, и показывает точную команду для повторного запуска.
